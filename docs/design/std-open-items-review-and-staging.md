## 1. 评审方法

- **正席**：支持「建新类型／做变更」的一侧，列收益与不可替代性。
- **反席**：支持「维持现状／不做」的一侧，列成本、宿主污染、破坏面。
- **结论**：明确采纳一侧，并写清判断依据来自本方案已有判据（§1.1、§1.5、§1.2、§1.7），以及新增准绳 §1.8「指针不对外，包内消化」。
- 结论分三种：**建议采纳**（可直接进裁定）、**建议否决**（维持现状）、**条件性**（只有满足边界条件才成立）。

## 2. 逐项评审

### 2.1 `Fd` 的形态判定

**正席（寄生 `int`）**：fd 本来就是 `int`，CT 允许标量作宿主；`fd.close()` 比 `Fd.close(fd)` 短；零装箱、零新类型，与 libc 完全同形。

**反席（建类型）**：把 `close`/`read`/`write` 挂到 `int` 上，会让**所有整数**获得这些方法（`42.close()`），比 `size.year()` 的宿主污染严重得多；`open()` 的返回值无法在类型上表达 `own`，漏调 `close` 没有兜底；与 `IoFile`、`Socket` 的关闭语义会形成三套入口。

**结论：建议采纳反席——不寄生 `int`，`Fd` 建成 ③ 资源类型**（不透明指针 + `own` + `Drop`，`close()` 幂等）。若确需与多路复用配合，只暴露只读的 `raw_fd()` 取值。

**依据**：§1.5 的两步判定是「先判寄生，判不掉才建类型」。此处的判不掉不是技术不可行，而是**宿主污染 + 所有权不可表达**；这与会污染所有 `long` 的时间方法（Q8 已否）同构。§1.8 进一步要求：只能以裸整数句柄交出的能力应包成对象，释放责任留在包内。

**影响面**：§2.4 `Fd` 行、§2.8、§7 P3/P6。

### 2.2 `Timer` 的形态判定

**正席（建类型）**：POSIX 定时器（`timer_create` 族）是系统资源，必须显式删除；`arm`/`disarm`/`wait` 有接收者；`Drop` 能兜底。

**反席（不建类型）**：如果 `Timer` 只是「计时/测耗时」，它不持有任何资源，建类型属于过度设计；`timer_t` 的平台宽度不一，装箱后每次与 libc 互操作都要转换。

**结论：条件性——把两种语义拆开**：

1. **资源型定时器**（`timer_create`/`timer_settime`/`timer_delete`）→ ③，不透明指针 + `Drop`，名字保留 `Timer`；
2. **耗时测量**（起止时间差）→ 不建类型，用 `Time` namespace 的纯函数（如 `Time.monotonic_nanoseconds()`）＋减法。

**依据**：§1.5 只给「真的持有资源」建类型；测耗时只产出数值，属 ①。资源型定时器按 §1.8 必须是可 `own`、可自动释放的对象，不能以裸 `timer_t` 句柄交出。

**影响面**：§2.7 `Timer` 行、§2.8、§7 P5/P6。

### 2.3 A3：`DIR *` → `Dir`

**正席**：`DIR *` 是不透明类型，CT 看不到定义；裸指针无法挂方法；`closedir` 必须有人兜底；`next()` 需要接收者；`Drop` + `close` 幂等能消除最常见泄漏。

**反席**：每个句柄一次 `malloc`；`readdir` 的 `struct dirent` 仍只能在 shim 内拷出；与现有 `list(out, cap)` 功能重复；平台差异要写文档。

**结论：建议采纳正席——建 `Dir`（③ + `Drop`）**，`list` 保留为一次性便捷路径；文档写明「流式用 `Dir`、一次性用 `list`」。

**依据**：§1.5 命中「一次创建、多次共享、必须显式关闭」；`DIR *` 无法命名，寄生路径不存在。按 §1.8，只能以裸指针交出的能力必须包成对象。

**备注**：§1.5 已写「已定 `Dir`、`Socket`」，若该句视为负责人裁定，则本项不构成新裁定，评审不翻案。

**影响面**：§2.5、§2.10 A3、Q11。

### 2.4 A4：`int`（fd）→ `Socket`

**正席（寄生 `int`）**：fd 是整数，`send`/`recv` 直接挂最短；不新增类型。

**反席（建类型）**：所有整数都会获得 socket 方法，宿主污染；`accept()` 产生新 fd，所有权无法表达；`close` 与 `Fd`/`IoFile` 冲突；`connect` 需要 DNS 解析与释放，不适合挂在裸 `int` 上。

**结论：建议采纳反席——`Socket` 建成 ③ 资源类型**，不寄生于 `int`；`raw_fd()` 是否暴露由 P7 决定。

**依据**：与 §2.1 同构——宿主污染 + 所有权不可表达；且 §2.7 已把 `Socket` 定位为 OO2。按 §1.8，裸 fd 句柄必须由对象包住，释放责任留在包内。

**影响面**：§2.7、§2.10 A4、Q11、§7 P7。

### 2.5 A5：数组／列表是否建 struct

**正席**：多结果（`split_into`、目录项）用列表可遍历、可 `Drop`、长度显式；调用方缓冲在数量不定时不好用。

**反席**：语言侧已内置 `Vec`；本仓再建 `StrList` 会出现第三套集合写法；当前需求已被 `list(out, cap)` 与 `split_into(separator, out, cap, slot_size)` 覆盖；新类型要定义深浅拷贝与元素释放责任。

**结论：建议否决——不引入列表 struct**。继续用缓冲式 API；将来确需动态集合时，用语言侧内置 `Vec`，不由本仓自建。

**依据**：§1.4 已定「不重复定义内置类型」；§1.5 的资源判据不适用于纯数据集合。

**影响面**：§2.10 A5、Q12、§2.1/§2.5。

### 2.6 Q1：`std/io/File.m.ct` 拆不拆

**正席（拆）**：`Path` 与 `File` 单职责；`exists`/`rename` 不该与文件句柄混在一个 unit。

**反席（不拆）**：`open` → `read`/`write`/`close` 是连续 API 面，拆开对消费者是 import 成本；0.4.0 已计划 `String` → `CStrOps` 改名，叠加拆分扩大破坏面。

**结论：建议否决拆分**。0.4.0 只改 trait 名，`File.m.ct` 保持一个 unit；若 `Path` 将来需要独立演化，另开 issue。

**依据**：§1.7「整块交付」与最小破坏面原则。

**影响面**：§4.3、Q1、§7 P0。

### 2.7 Q2：`IoFile` 包装体不释放要不要修

**正席（修）**：`close` 只 `fclose` 不释放包装体，是确定的泄漏；修法：`close()` 幂等并释放包装体，或改为 `own IoFile *` + `Drop`。

**反席（不修）**：破坏性变更；调用方若在 `close` 后继续用指针会 UAF；双 `close` 需要防护。

**结论：建议采纳正席，但按破坏性变更处理**：0.4.0 起 `close()` 幂等且释放包装体，随版本通告；不静默改变现有行为。

**依据**：§8.1 已把该条列为已知缺陷；幂等 `close` 是包内既有约定（§5.4）。

**影响面**：§8.1 风险行、Q2、§7 P3。

### 2.8 Q3：`char *` 名字数量要不要设上限

**正席（设上限）**：当前 50 个名字，已接近认知上限；硬上限能逼迫合并或分层。

**反席（不设）**：固定数字会逼出更差的命名或过早建类型；§1.2 的准入判据已经在控质量；名字数量与模块能力成正比。

**结论：建议否决硬上限，改为软阈值**：维持 §1.2 判据与同宿主查表；超过 60 个触发一次复审，不预设合并。

**依据**：§1.2 已把「是否明显更短、更自然」作为准入判据，硬数字与判据冲突。

**影响面**：§5.2、§8.1、Q3。

### 2.9 Q9：`Math` namespace 是否退役

**正席（退役）**：`Math.sqrt(x)` 与 `x.sqrt()` 是两套写法，统一到方法层更 CT。

**反席（不退役）**：`Math` 是既有接口，退役破坏兼容；无接收者场景（常量表达式、静态计算）仍自然；D1 已登记保留。

**结论：建议否决 0.4.0 退役**。新能力只加 `Float`/`Real` 方法层；`Math` 退役留到 1.0 评估，且必须先有兼容策略。（负责人后续裁定直接删除 `Math` namespace，本节建议不采用；以裁定为准。）

**依据**：§1.7 的破坏面控制；D1 的「namespace 不再扩张」已足够限制两套写法扩散。

**影响面**：§3.6 D1、Q9。

### 2.10 Q11、Q12

- **Q11（`Dir`/`Socket` 接受 struct 对等类型，还是用别名/裸类型宿主）**：结论同 A3、A4——**接受 struct 对等类型**，不用裸类型宿主；Q11 已定。
- **Q12（数组/列表类结果是否引入列表 struct）**：结论同 A5——**不引入**；Q12 关闭，状态为“不做”。

**影响面**：§2.10 A3/A4/A5、§8.2 Q11/Q12。
