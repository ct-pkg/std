# `std` 待办：包身份、发布卫生与能力缺口

| 项 | 值 |
| --- | --- |
| 性质 | 待办台账：只登记与验收，不改 `ct.pkg`、不动版本号、不打 tag |
| 基线 | `0.3.1`；默认分支 `main` |
| 日期 | 2026-11-15 |

## 1. 前置能力（用本仓能判断的说法）

| 能力 | 现状 | 影响 |
| --- | --- | --- |
| 包管理器能从索引读到发布者标识 | 未具备 | 清单里的 `publisher` 只能是声明，无法验证生效 |
| 包管理器能把包的命名空间根接入 `-I` | 未具备 | `ns-root` 同上，`import std::<mod>::<Unit>` 的解析仍靠调用方手写 `-I` |
| `ct build` 能默认读取 lock | 未具备 | 依赖的版本锁定无法验收 |

这三项具备之前，改动 `ct.pkg` 的身份字段或依赖写法都只会得到「声明了但不生效」的中间态。

## 2. 待办

### 2.1 包身份声明可验收

**为什么**：消费方需要区分同名包，并让 `import std::<mod>::<Unit>` 按包声明的命名空间根解析，
而不是靠每个调用方手写 `-I` 路径。

**做什么**：在 `ct.pkg` 声明 `publisher = ct`、`ns-root = .`。两项已在 `ct.pkg:39-40`，当前被
包管理器接受但不生效（`ct.pkg:31-36` 已注明）。

**验收**：前置能力具备后，`ct pkg check .` 返回 `RC=0`，且从索引安装后 `import` 能按 `ns-root`
解析。

**现状**：声明已具备；验收被前置能力阻塞。**本仓不在此之前改这两个键、不打 tag。**

### 2.2 tag 必须落在默认分支历史内

**为什么**：游离 tag 会让「按 tag 复现」拿到分支上不存在的树，发布物与主线对不上。

**做什么**：每次发布把 annotated tag 打在默认分支历史内的提交上；发现游离 tag 时并回默认分支，
或按新版本重打。

**验收**：`git merge-base --is-ancestor <tag> main` 返回 `RC=0`。

**现状**：`v0.2.0` 已满足（`git rev-parse v0.2.0^{}` 指向 `b04b7d6`，在 `main` 历史内）；
后续发布沿用同一检查。

### 2.3 依赖写法：全名 + 版本范围

**为什么**：裸包名在多个发布者共存时无法定位；依赖图需要可唯一解析。

**做什么**：一旦引入包依赖，一律写成 `<publisher>/<name>@<range>`，不写裸名。

**验收**：引入首个依赖后，依赖图内包名唯一，且 `ct pkg check .` 返回 `RC=0`。

**现状**：当前没有任何包依赖；`ct.pkg:43` 的 `requires = ct >= 0.30.0` 是编译器下限，不是包依赖。
本条目暂时没有可执行对象，等首个依赖出现时适用。

### 2.4 应用层能力缺口

四个子项各自判断，不打包成一个决定。全部只做评估，不排期。

| 子项 | 为什么需要 | 做什么 | 验收 | 现状 |
| --- | --- | --- | --- | --- |
| 字符串增量 | 反向查找、忽略大小写比较、带错误报告的数值解析现在要么手写、要么用 `atoi` 无法区分失败 | `rfind_char`、`compare_ignore_case`、`parse_long` / `parse_llong` / `parse_ulong` / `parse_real` | `tests/str/` 覆盖未命中与非法输入；`tests/run.sh` 全绿 | 方案见 [issue 0001](../issues/0001-str-string-trait-rename.md) 与 [设计提案 §2.1](design/std-scope-and-presentation.md) |
| 原子写 | 现有 `write_file` 是整文件替换（`std/fs/README.md:10`），中途失败会留下半截文件 | 评估 `write_file_atomic`：同目录临时文件 + 写入 + `rename` | 断电/失败场景留下旧文件或完整新文件，不出现半截；fixture 断言 | 未实现；`rename` 已有（`Fs.rename`） |
| 文件属性查询 | 调用方需要大小/权限/时间，但不想为 `stat` 的 C 结构体布局建模 | 提供 `file_size()` / `file_mode()` / `file_mtime()` 三个查询 | 三个值分别有 fixture；文档写明每次一次 `stat` | 方案已定（[设计提案 §2.5、§2.8](design/std-scope-and-presentation.md)）；未实现 |
| UTF-8 显示宽度 | `count_codepoints()` 只数码点，终端列宽（东亚宽字符、组合符）算不出来 | 评估 `count_columns`：按码点区间判定宽度 | 中日韩全角、组合符、emoji 各有用例 | 未实现；现有能力仅 `decode` / `count_codepoints` / `encode`（`std/utf8/README.md:80`） |

不做的一项：`Map` 已由编译器内置层提供，本包不再提供 `std::map`（`ct.pkg:18-21`）；
`Vec` 的泛化属内置层，同样不在本包。本仓不为这两项排任何工作，也不把它们转成别处的任务。

### 2.5 是否新建上层包

五个候选，逐个给结论；均不新建。

| 候选 | 结论 | 本仓理由 |
| --- | --- | --- |
| `arena` | 已有，不新建 | `std::arena` 的 `Arena` + `ArenaOps` 已在（`std/arena/Arena.h.ct`） |
| `string` | 不新建 | `std::str` 覆盖 `char *` 借用层（拟改 `CStrOps`），拥有型字符串由内置 `Str` 提供；再建包会出现第三套写法 |
| `result` | 暂缓 | 需要语言级「可判错的结果/联合类型」能力；方法层无法自造一套可靠的错误联合体 |
| `sync` | 不做 | 并发/同步属语言与运行时能力，不在本包边界内（[设计提案 §1.4](design/std-scope-and-presentation.md)） |
| `callback` | 暂缓 | 需要语言级函数指针/回调能力；契约应由语言层定义后再谈包装，本仓不预设签名 |
