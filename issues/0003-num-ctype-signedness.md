# `char` 宿主上的 ctype 谓词：有符号字节的可移植性缺陷

| 项 | 值 |
| --- | --- |
| 状态 | 待排期；本机不可复现，属可移植性缺陷 |
| 影响 | 不改变现有 API；新增 7 个方法沿用同一口径，并补契约文字 |
| 关联 | [设计提案 §2.2](file:///Users/samxx/trae-ws/std/docs/design/std-scope-and-presentation.md) |
| 验证情况 | 本机仅验证了「`char` 有符号、且本机测不出差异」；标准层面结论为**推断，未在 musl 等实现上验证** |

## 1. 问题

`std::num::Char` 的谓词把 `char` 直接交给 `isalpha` / `isalnum` / `toupper` 等。C 标准规定这些函数的
参数必须是 `unsigned char` 可表示的值或 `EOF`；负值（`EOF` 除外）是**未定义行为**。

`char` 是否有符号由实现决定。本机为有符号：UTF-8 多字节字符的单个字节，例如 `0xC3`，作为 `char`
读出来是 `-61`，直接传入即为负值。glibc 的 ctype 表对 `-128..255` 都做了覆盖，所以本机看不出问题；
换到只保证标准行为的实现（如 musl）就没有这个保证。这是可移植性缺陷，不是本机可复现的功能 bug。

## 2. 判定依据（讲清即可，不贴标准原文）

- 标准口径：`isalpha` 等接受 `EOF` 或 `unsigned char` 范围内的值；其它负值行为未定义。
- 本机探测（`char` 有符号，`0xC3` → `-61`）：
  ```
  char_signed=1 value=-61
  isalpha_raw=0
  isalpha_unsigned=0
  ```
  原始 `char` 与 `(unsigned char)` 两种写法在本机都返回 0，**因此本机用例无法区分对错**。
- 结论：本机不能作为「已经安全」的证据；也无法通过本机运行复现缺陷。

## 3. 现状核验（重要，避免误判成待修缺陷）

本仓现有实现**已经**做了 `(unsigned char)` 转换：

- `std/num/Num.shim.h` 中 7 个 ctype 调用全部带 `(unsigned char)`，包括 `is_upper` / `is_lower`
  （`:107-131`）与 `to_upper` / `to_lower`（`:97-105`）。
- 因此现有 7 个 `is_*` 与 `to_*` 在源码层面是安全的，不存在「忘记转换」的实际缺陷。

本条剩下的工作不是修现有转换，而是三件事：

1. 把口径写进 `std::num` 的契约：**所有 `c` 类谓词按无符号字节解释**，`char` 宿主上的方法一律如此；
2. 新增的 7 个谓词按同一口径实现，不允许直接转发原始 `char`；
3. 加防回归手段（静态检查或代码评审清单），避免后续 helper 漏掉转换。

## 4. 方法清单

宿主均为 `char`，模块 `std::num`，返回 `int`：

| 方法 | 状态 | 语义 |
| --- | --- | --- |
| `is_digit()` `is_alpha()` `is_space()` `is_upper()` `is_lower()` | 已有 | 按无符号字节判定 |
| `to_upper()` `to_lower()` | 已有 | 按无符号字节转换，返回 `int` |
| `is_alnum()` | 新增 | 字母或数字 |
| `is_punct()` | 新增 | 标点 |
| `is_print()` | 新增 | 可打印（含空格） |
| `is_graph()` | 新增 | 可打印（不含空格） |
| `is_cntrl()` | 新增 | 控制字符 |
| `is_blank()` | 新增 | 空格或制表符 |

## 5. 契约文字（要写进 `std/num/README.md`）

> 所有接收 `char` 的判定/转换方法都按**无符号字节**解释：实现内部先转换为 `unsigned char` 再调用
> C 库。因此 `0x80..0xFF` 的 UTF-8 单字节不会被当作负值，行为与平台无关。
>
> 返回值：非 0 表示真。**不保证等于 1**——C 库可能返回任意非零值；需要布尔值时用 `!= 0`。

（当前实现返回的是 C 库原始非零值，不是归一化的 0/1。是否归一属于契约变更，见 §8 待定。）

## 6. 验收判据

1. **边界用例**：`((char)0xC3).is_alpha()` 期望 `0`；`((char)0x41).is_alpha()` 期望非 0。
2. **本机不能作为通过依据**：上述边界用例在本机对「原始 `char`」与「`unsigned char`」都返回 0
   （见 §2 探测），单靠运行结果无法证明修复有效；必须配合下一条。
3. **静态检查**：`std/num/Num.shim.h` 中每个 ctype 调用（`isalpha`、`isalnum`、`ispunct`、`isprint`、
   `isgraph`、`iscntrl`、`isblank`、`isxdigit`、`toupper`、`tolower`）都必须带 `(unsigned char)`；
   可用 `grep` 作为文档检查，或加入 `tests/run.sh` 的静态闸门（属实现决定）。
4. **契约落地**：`std/num/README.md` 出现 §5 的文字；7 个新方法各有 fixture 用例。
5. `tests/run.sh` 全绿。

## 7. 影响面

- `std/num/Num.m.ct`：`Char` trait 新增 7 条声明与映射。
- `std/num/Num.shim.h`：新增 7 个 helper，全部带 `(unsigned char)`。
- `std/num/README.md`：契约文字 + API 表 + 可移植性说明。
- `tests/num/main.ct`：新增 7 个方法用例，以及 §6 的边界用例（标注「本机不可作为通过依据」）。
- `README.md` §4 的 `char` 宿主名字表：新增 7 个名字。
- 设计提案 §2.2 同步。
- 现有 7 个方法**不改行为**，仅补契约文字。

## 8. 待定与保留名

- **待定**：`is_*` 是否归一化返回 `0/1`。现状返回 C 库原始非零值（如 `isalpha` 可能返回 1024），
  改为 `0/1` 是契约变化，需 owner 决定；本条默认**不改**。
- **保留名**：`max` / `min` 在 `int` / `long` / `long long` 宿主上已是封闭保留名，
  新增查询不得占用；需要带上下限的查询必须另起名字并单独评审（例如 `clamp` 已有，不得再造同义名）。
